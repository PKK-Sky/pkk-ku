## Kesimpulan yang relevan untuk pekerjaan frontend

1. **Migration #12 (`admin_can_select_announcements`) sudah aktif** — jadi `getAllAnnouncementsForAdmin()` dan rencana `AdminAnnouncementsScreen` (lihat `ACUAN-BUILD-UI-FRONTEND.md` §6.2) **sudah bisa langsung dipakai tanpa migration tambahan**, RLS-nya sudah benar di sisi database.
2. **Tidak ada migration yang membuat kolom `crop_x/y/width/height` menjadi check-constrained ke rentang 0–1** — ini murni **kontrak konvensi** (dikonsumsi oleh Edge Function `generate-report-pdf`), bukan dipaksakan oleh database. Artinya bug crop-dalam-pixel (§0.5 bug #2 di `ACUAN-BUILD-UI-FRONTEND.md`) **tidak akan pernah muncul sebagai error saat insert** — ia akan lolos ke database dengan tenang lalu menghasilkan PDF dengan crop yang salah posisi. Ini justru membuat bug tsb lebih berbahaya (silent failure), bukan lebih ringan.
3. **Modul Feed (`posts` dkk.) dan Chat sudah lengkap di database** sejak migration #3–#5, jauh melampaui apa yang sudah dibangun di sisi UI (baru moderasi admin untuk Feed, chat belum ada UI sama sekali). Ini area pengembangan lanjutan yang backend-nya sudah siap.
4. **3 cron job aktif**: pembersihan post kedaluwarsa tiap jam, pembersihan `phone_check_attempts` tiap hari jam 3 pagi, dan pengiriman push notification tiap menit. Tidak ada yang perlu diubah dari sisi frontend, sekadar konteks bahwa data `posts` yang sudah lewat `expires_at` akan **hilang otomatis** dalam ≤1 jam (bukan hanya disembunyikan RLS) — relevan kalau nanti admin butuh "riwayat" post lama, karena baris fisiknya memang akan terhapus, bukan cuma tidak muncul.
